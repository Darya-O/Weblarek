Структура проекта:
- src/ — исходные файлы проекта

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

#### Модели данных
В приложении существуют три класса-модели, каждый из которых отвечает за собственную область данных и инкапсулирует всю логику работы с ней.

#### Класс ProductCatalog (каталог товаров)
Область ответственности: этот класс ведёт учёт всего ассортимента доступных товаров и управляет состоянием «выбранного в данный момент товара» для показа подробной информации. Он не касается содержимого корзины и не хранит персональные данные клиента.

Конструктор: constructor() – не требует аргументов; наполнение каталога осуществляется через публичные методы.

Поля класса:

private products: IProduct[] – список всех товаров, имеющихся в продаже (массив объектов, соответствующих интерфейсу IProduct).

private selectedProduct: IProduct | null – товар, который выбран для детального просмотра; если ничего не выбрано – null.

Методы:

setProducts(products: IProduct[]): void – загружает переданный массив как актуальный каталог.

getProducts(): IProduct[] – возвращает полный список товаров из каталога.

getProductById(id: string): IProduct | undefined – выполняет поиск товара по его уникальному id; при отсутствии возвращает undefined.

setSelectedProduct(product: IProduct): void – фиксирует товар для показа в режиме детального просмотра.

getSelectedProduct(): IProduct | null – возвращает текущий выбранный товар либо null, если таковой не установлен.

#### Класс Cart (корзина)
Область ответственности: класс управляет наполнением корзины покупателя. Он содержит перечень товаров, отобранных для покупки, и предоставляет инструменты для изменения этого перечня, а также для подсчёта итоговых показателей (общая сумма, число позиций).

Конструктор: constructor() – без параметров; корзина изначально пуста.

Поля класса:

private items: IProduct[] – массив товаров, которые в данный момент лежат в корзине (элементы соответствуют интерфейсу IProduct и могут быть как копиями, так и ссылками на объекты из каталога).

Методы:

getItems(): IProduct[] – возвращает актуальный список всех позиций в корзине.

addItem(product: IProduct): void – добавляет указанный товар в корзину.

removeItem(productId: string): void – удаляет из корзины товар с заданным productId (если таких несколько – убирается первый попавшийся).

clear(): void – полностью очищает корзину.

getTotalPrice(): number – вычисляет суммарную стоимость всех товаров в корзине: для подсчёта берётся поле price; если у товара цена равна null, он считается бесплатным (цена 0).

getItemCount(): number – возвращает общее количество товаров (длину массива items).

hasItem(productId: string): boolean – проверяет, присутствует ли в корзине товар с переданным идентификатором; возвращает true при наличии, иначе false.

#### Класс Buyer (покупатель)
Область ответственности: хранит данные о покупателе, необходимые для оформления заказа, и занимается их проверкой. Класс устроен так, что позволяет изменять отдельные поля по отдельности, не затрагивая остальные, а также даёт детальную информацию об ошибках в заполнении.

Конструктор: constructor() – без параметров; все данные устанавливаются через методы.

Поля класса:

private payment: TPayment | null – выбранный способ оплаты (может быть null, если ещё не указан).

private email: string = '' – электронная почта.

private phone: string = '' – контактный телефон.

private address: string = '' – адрес доставки.

Методы:

setData(data: Partial<IBuyer>): void – частично обновляет информацию о покупателе: принимает объект с любым набором полей из IBuyer и заменяет только те, что переданы, остальные оставляя без изменений.

getData(): IBuyer – возвращает полный объект с текущими данными покупателя, соответствующий интерфейсу IBuyer.

clear(): void – сбрасывает все поля: строковые становятся пустыми, а payment становится undefined.

validate(): BuyerValidationErrors – проверяет корректность заполнения всех полей. Результат – объект, в котором ключи – это имена полей, а значения – сообщения об ошибках для тех полей, что не прошли проверку. Если поле заполнено верно, оно отсутствует в выдаче. Правило: поле считается невалидным, если его значение – пустая строка. Пример возврата при ошибках: { payment: 'Не выбран вид оплаты', email: 'Укажите email' }. Если все поля заполнены, возвращается пустой объект {}.

#### Слой коммуникации
#### Класс ApiService
Область ответственности: выступает посредником между приложением и сервером. Обеспечивает загрузку каталога товаров и отправку оформленного заказа.

Конструктор: принимает параметр api: IApi – экземпляр готового API-клиента из начального набора.

Методы:

getProducts(): Promise<IProductsResponse> – отправляет GET-запрос на эндпоинт /product/ и возвращает промис с объектом, содержащим массив товаров и их общее количество.

sendOrder(orderData: IOrderRequest): Promise<IOrderResponse> – отправляет POST-запрос на эндпоинт /order/ с данными заказа (список товаров и информация о покупателе). В ответ приходит объект подтверждения, содержащий идентификатор заказа, итоговую сумму и служебное сообщение.

Зависимости: использует типы, описанные в types/index.ts.
